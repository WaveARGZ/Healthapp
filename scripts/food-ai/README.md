# 食事写真の継続学習

## 現在の方式：Driveのみ保存・手動起動（2026-10-15）

[streaming/README.md](streaming/README.md) が新しい運用手順です。`npm run food-ai:launcher` で管理画面を起動します。
以下の従来方式の収集・レビュー・学習・アーカイブコマンドはPCへファイルを書き込むため、現在の運用では実行しません。既存ファイルは読み取り専用の移行元・履歴として保持します。新方式は実認証・非公開フォルダ作成・Drive直接保存と完全再取得照合まで確認済みです。GAS反映・実利用者写真の送信・実CLIP統合評価は未完了です。

## 旧方式の記録（参考のみ・実行しない）

既存のCLIP画像モデルを固定し、料理の候補順位を補正する層をPCで学習します。本番は27分類、ローカルのテスト用は枝豆を加えた28分類です。公開収集画像を使う基本モデルの改善と、利用者が本番で修正する付加データは別管理です。量やカロリー・PFCの写真推定は対象外です。

## 定期サイクル

このチャットのスケジュールから6時間ごとに実行します。PCとCodexを起動しておいてください。Codexの利用枠を使い、学習処理はPCで動きます。AWSの追加リソースや有料の推論APIは使用しません。

1. リポジトリで `npm run food-ai:agent -- --collect-only` を実行。公開画像を最大300枚追加し、未確認画像から72枚を選びます。取得元のAPI上限で早く止まる場合も正常です。
2. `ml/artifacts/review-queue/queue.json` が示す一覧画像を実際に開いて確認。必要なら原画像を開きます。料理名・モデルスコアから正解を推測しないでください。
3. 明確な主料理をテスト用ラベル（現在28分類）から選びます。食品でないもの、図、区別できないもの、混合料理で主料理不明なものは除外。判定JSONを `ml/artifacts/` 内に保存します。
4. 下記の記録コマンドで確認結果を反映し、`npm run food-ai:agent -- --skip-collect` を実行します。
5. `ml/artifacts/agent-latest.json` と、その中の `runDir` の評価レポートを確認します。確認済み評価の改善条件を満たせば3001番用の補正器が更新されます。

```bash
npm run food-ai:review
npm run food-ai:review:apply -- --data training-data/commons \
  --decisions /絶対パス/判定.json --reviewer "Codex visual review"
npm run food-ai:agent -- --skip-collect
```

判定ファイルは次の配列です。画像ハッシュは `queue.json` から取得し、画像そのものを確認してから判定を記入します。除外する場合は `foodId: null`。`notes` は実際に見えた内容と判定理由です。

```json
[
  {
    "id": "commons-123",
    "imageSha256": "queue.jsonに記録された64文字のSHA-256",
    "foodId": "ramen",
    "notes": "丼の中に中華麺とスープが明確に写っている"
  }
]
```

記録は `visual-agent` として保存され、人による確認とは区別されます。既存の確定判定と異なる結果、写真変更後の古いハッシュ、パスを含むIDは拒否します。人が直接作る確認記録では `review.method: "human"` を使用できます。画像確認を経ていない状態で `labelVerified` を変更しないでください。

## 採用条件と保存先

- 基本データ：`training-data/commons/`。出典・作者・ライセンスは `sources.json`。自動収集ラベルは未確認のまま保存します。
- 実行結果：`ml/artifacts/runs/<実行日時>/`。既存レポートは上書きせず、最新の要約を `agent-latest.json` に保存します。
- 分割台帳：`verified-splits.json` と `research-splits.json`。追加収集で既存の学習画像がテストに移らないようにします。過去の近似画像も追跡します。台帳を削除して評価をやり直さないでください。
- 目視で判明した同一撮影場面：`ml/artifacts/verified-exclusions.json` に画像ID・SHA-256・根拠・確認者・日時を保存します。通常の近似ハッシュで検出できない納豆の同一場面6枚は、学習・検証・テストの全てから除外しました。元の写真・正解・過去の分割割当ては保持します。ハッシュ不一致や台帳の不正は学習を停止し、画像差し替えを黙って通しません。別データセット用には `--exclusions FILE` で台帳を明示できます。未監査の撮影場面重複を完全に排除できる保証ではありません。
- 確認済み学習：独立写真100枚・5分類以上、検証とテスト各15枚以上から実行。確認済みラベルの画像だけを使います。
- 自動採用：対象の全分類（テスト用は28分類）に独立写真10枚以上、各分類の学習5枚・検証2枚・テスト2枚以上。ベースモデルと現行モデルの両方を改善し、全体・分類別の上位1位/5位の成績と対応のある比較を検査します。具体条件と不合格理由は `evaluation.json` に残ります。
- テスト用モデル：`lib/food-ai/test-calibration.json`。本番は `lib/food-ai/deployed-calibration.json` を使用。自律サイクルから本番のファイル更新・GitHubへのpush・AWS操作はしません。
- データ不足時：仮ラベルを含む研究実験を別レポートに保存できます。既に除外した画像は使いません。仮ラベルとの一致率は実際の精度ではなく、モデルの採用にも使いません。

検証データで学習設定を選択し、固定のテストデータで回帰確認します。同じテストの反復評価は新しい未知データでの検証ではありません。公開前には、実際のスマホ写真による独立評価も必要です。

## 実行量と復旧

Commonsは1回最大300枚、1分類の候補上限10,000枚、ローカルデータ上限1GB、工程ごとの上限20分です。空き容量5GBを確保できない場合は取得を停止します。写真・確認・学習コード・分割台帳・現行モデルが変わらなければ学習を省略します。収集は継続位置を保存し、通信失敗時は次回に再開できます。明確な失敗は要約に残し、モデルを更新しません。

不足しやすい料理には日本語・英語の別表記（冷奴 / hiyayakko、食パン / shokupan、yogurt / yoghurt など）の検索も用意しています。検索語の追加時も既存の継続キーを残し、写真ID・ハッシュで重複取得を防ぎます。検索に一致したことは正解の証明ではなく、すべて目視確認待ちです。確認で除外した画像を件数確保のために再採用しないでください。

特定の間違いに対応するときは、例えば `npm run food-ai:collect -- --labels edamame,natto --max-new 60 --per-label 10000` で対象を限定できます。他の料理の継続位置、既存写真、容量・API制限は維持します。収集後の目視確認と固定分割での評価は省略しません。枝豆は緑色の莢や豆の形状を確認し、グリーンピース、別の豆、混合料理など判別できない写真を枝豆の正解にしないでください。

テストの候補は `lib/food-ai/test-photo-labels.json`、本番は `photo-labels.json` で管理します。候補を追加することと、補正器の学習・採用は別です。`food-ai:learn` の既定の反映先もテスト用になっています。明示的に本番の `deployed-calibration.json` を指定した場合だけ本番ラベルを使用しますが、この自律サイクルでは行いません。既存キャッシュはラベル・プロンプトを含む指紋で分離されます。本番APIの学習シグナルは27分類のままなので、28分類を本番へ移す前にAPIスキーマ・モデル互換性と実写真を別途検証してください。

同時実行はロックで防ぎ、終了済みプロセスのロックは回復します。強制終了で回復用ロックが残った場合は、記録されたPIDの終了を確認してから対処してください。画像・JSON・確認結果は削除しません。

手動で再検証する場合は `npm run food-ai:agent -- --skip-collect --force`。毎回同じ写真で強制学習する必要はありません。スケジュール停止・頻度変更はCodexのスケジュール画面から行います。

## 大規模データとDrive

すべてのクラウド保管先はユーザー指定の [foodDB](https://drive.google.com/drive/folders/1qumdyNBQbUoQWgQHcI_6BpYnzYlNB9iW) 内です。今回の専用フォルダは [公開画像ベース学習_継続収集_20261009](https://drive.google.com/drive/folders/1-43fJG6gRjTVX0FPSi4_-sfRsSmP-hJT)。既存の学習データ・利用者の修正情報は移動・削除・自動混合しません。

```bash
npm run food-ai:collect:nutrition -- --max-new 1000 --max-bytes 1000000000
npm run food-ai:archive -- prepare
npm run food-ai:archive -- prepare --dataset nutrition5k --data training-data/nutrition5k --max-batches 10
```

- Nutrition5kの公式CC BY 4.0画像と材料・重量・kcal/PFCの提供元データを別フォルダに取得します。元CSV・公式train/test・画像ハッシュ・出典を保持します。料理名分類とは異なる教師情報なので、現在の順位補正学習には自動混合しません。元データの欠損名は補完せずnull、公式splitにない画像は隔離します。
- 写真は最大1,000枚・転送1GB/回、PC空き5GBを確保します。3,490件の真上RGB索引と5,006皿分の栄養表がありますが、同じ皿の追加盛り付けは独立した事例ではありません。既存Driveの200枚と重複する可能性もあります。
- Driveは100MB以下の差分tarで保管。新規保存先の全データセット合計を、未転送予約も含め4TB（4,000,000,000,000 bytes）で制限します。アカウント全体の残量を保証する設定ではなく、4TBを必ず埋める目標でもありません。追加容量購入や課金サービスの有効化は行いません。
- アーカイブ準備はアップロードではありません。Driveコネクタで送信し、取得し直した内容のハッシュが一致してから受領記録を保存します。途中失敗時は元データを保持し、保存完了とは扱いません。詳細は [Drive運用](./DRIVE-ARCHIVE.md)。
- 保存を検証した後は `node scripts/food-ai/drive-archive.mjs cleanup` で対象を確認し、`--apply` を付けて転送用tarだけ整理できます。Nutrition5kの画像も `node scripts/food-ai/nutrition5k-cache.mjs` で確認後に `--apply` でPCから退避できます。画像と正解JSONの両方に完全再取得済みの証跡が必要です。元CSV・正解JSON・復元索引は残り、次回は未取得分から継続します。[復元手順](./nutrition5k-cache.md)を参照してください。学習中のCommons画像はこの処理では削除しません。
- `node scripts/food-ai/snapshot-learning.mjs` で公開データ用の学習コード・評価・分割台帳のスナップショットを作成できます。出力先を `--data` に指定して `food-ai:archive -- prepare --dataset learning-runs` で同じDrive保存待ちキューへ追加してください。秘密情報やアプリ利用者の写真は収録しません。スナップショットも実アップロード・再取得照合が必要です。
- 公開権利を一次情報で確認した取得元は [dataset-sources.json](./dataset-sources.json)。研究限定・権利不明のソースは除外します。MyFoodRepoの大量データは公式配布先のログインが必要で、認証を迂回して取得しません。

大量収集がそのまま精度向上になるわけではありません。画像の数・栄養表の件数・目視確認済みの料理名・独立した評価写真の数を別々に報告します。
